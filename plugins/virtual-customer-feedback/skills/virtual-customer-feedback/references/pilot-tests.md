> **설치 직후 1회 전량** + SKILL.md §2-5 주기(그 프로젝트 `log.md`에서 `가상고객[VCF-`로 시작하되 **실행 ID 대괄호 바로 뒤가 `] 후속`인 줄만 제외**한 수가 5의 배수에 도달)에 A·C군 재수행.
> 규칙 이행은 확률적이다. **문서에 썼다 ≠ 지켜진다.** 실제로 돌려 눈으로 확인한 것만 통과로 친다.
> 판정: 통과 / 실패 / 미실시 / 해당없음. **미실시를 통과로 적지 않는다.**
> **표기**: 아래 `/virtual-customer-feedback`는 **수동 설치 기준** 표기다. 플러그인으로 설치했으면 `/virtual-customer-feedback:virtual-customer-feedback`으로 읽고, 대화 지시("가상 고객 피드백 돌려줘")로도 같은 시험을 할 수 있다.

## H. 설치 확인·롤백

### H-1. 설치되는 것 — 파일 11개
```
<스킬 폴더>/SKILL.md
<스킬 폴더>/references/output-contract.md
<스킬 폴더>/references/modes.md
<스킬 폴더>/references/persona-index.md
<스킬 폴더>/references/persona-cards.md
<스킬 폴더>/references/sampling-record.md
<스킬 폴더>/references/ATTRIBUTION.md
<스킬 폴더>/references/pilot-tests.md
<스킬 폴더>/references/pilot-fixture.md
<스킬 폴더>/references/pilot-fixture-bc.md
<스킬 폴더>/references/pilot-fixture-neg.md
```
위 11개는 **스킬 파일**이다. `<스킬 폴더>`의 실제 위치는 설치 방식에 따라 다르다.

| 설치 방식 | `<스킬 폴더>` 위치 |
|---|---|
| 플러그인 (마켓플레이스) | `~/.claude/plugins/cache/<마켓플레이스>/<플러그인>/<버전>/skills/virtual-customer-feedback/`<br>실측 예: `~/.claude/plugins/cache/virtual-customer-feedback/virtual-customer-feedback/1.0.0/skills/virtual-customer-feedback/` |
| 수동 복사 | `~/.claude/skills/virtual-customer-feedback/` |

> **[사실] 위 경로는 2026-09-01 Windows / Claude Code 2.1.x에서 실측했다.** 다만 경로 규칙을 보장하는 공식 문서를 찾지 못했으므로 버전에 따라 달라질 수 있다 — 그때는 아래 탐색 명령으로 찾는다. 경로를 못 찾으면 이 대조는 **`미실시`로 적는다**(통과로 세지 않는다).
>
> **Windows**: `Get-ChildItem $(if($env:CLAUDE_CODE_PLUGIN_CACHE_DIR){$env:CLAUDE_CODE_PLUGIN_CACHE_DIR}else{"$env:USERPROFILE\.claude"}) -Recurse -Filter persona-index.md -ErrorAction SilentlyContinue | Select-Object FullName,LastWriteTime`
> **macOS / Linux**: `find "${CLAUDE_CODE_PLUGIN_CACHE_DIR:-$HOME/.claude}" -name persona-index.md -exec ls -l {} \; 2>/dev/null`
>
> 캐시 위치는 `CLAUDE_CODE_PLUGIN_CACHE_DIR`로 바뀔 수 있어 위 명령이 그 값을 먼저 본다. **여러 건이 나오면** 마켓플레이스 원본·구버전 캐시·활성 캐시가 함께 잡힌 것이다. `claude plugin list`가 보여주는 **버전 번호와 같은 경로 조각(`/<버전>/`)을 가진 것이 활성 설치본**이며, **그 하나만** §6-3과 대조한다. 활성본을 특정하지 못하면 **`미실시`로 적는다** — 다른 후보가 일치한다는 이유로 통과시키지 않는다.

> 플러그인으로 설치하면 스킬 파일 11개 외에 **플러그인 매니페스트(`.claude-plugin/plugin.json`)·`LICENSE`·`NOTICE.md`도 함께** 복사된다(플러그인 디렉터리 전체가 복사되므로). 스킬이 읽는 것은 11개뿐이다.

설치 후 `persona-index.md`·`persona-cards.md`의 SHA-256이 `sampling-record.md` §6-3과 일치하는지 대조한다.

`$r` / `r` 에 **위에서 찾은 `references` 폴더 경로**를 넣는다. 아래 기본값은 수동 설치 위치다.

**Windows (PowerShell)**
```powershell
$r = "$env:USERPROFILE\.claude\skills\virtual-customer-feedback\references"
Get-FileHash "$r\persona-index.md", "$r\persona-cards.md" -Algorithm SHA256 | Format-List Path, Hash
```

**macOS / Linux**
```bash
r=~/.claude/skills/virtual-customer-feedback/references
shasum -a 256 "$r/persona-index.md" "$r/persona-cards.md"
```

**두 파일 모두** 대조한다. 하나만 맞아도 통과로 세지 않는다.

> **[한계] 이 대조는 페르소나 팩 2개만 본다.** 규칙 문서(`SKILL.md`·`output-contract.md`·`modes.md`·`pilot-tests.md`)가 낡은 설치본이어도 이 검사는 통과한다. **규칙이 최신인지는 `plugin.json`의 `version`과 저장소 CHANGELOG를 대조해 확인한다** — 규칙을 고칠 때마다 버전을 올리는 것이 그래서 필요하다.

> 해시는 **LF 개행 기준**이다. 복사 과정에서 개행이 CRLF로 바뀌면 불일치한다 — 그때는 변조가 아니라 개행 문제다. 저장소의 `.gitattributes`가 LF를 강제하지만, 압축 해제 도구에 따라 바뀔 수 있다.

이 스킬을 고친 뒤 "검증했다"고 말하려면 아래를 전부 만족해야 한다. 하나라도 미실시·실패면 **미검증**으로 적는다.

1. **런타임 시험(A·B·C·D·E·F·G)을 규칙을 고친 세션이 아닌 새 세션이 수행하고 모두 통과.** 단 아래 한정 예외 2건을 둔다.
   - **F3·E6 한정 예외**: 두 시험은 `log.md`에 가짜 줄을 넣어야만 재현된다. 로그는 실제 역사를 담는 파일이므로 가짜 줄을 넣지 않고 **`미실시`로 남긴다.**

   - 표기 의무: 이 예외를 적용했으면 **`F3·E6 미실시`를 함께 적는다.** `전량 통과`라고 쓰지 않는다.

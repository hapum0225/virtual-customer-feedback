# 출력 계약 (output-contract) — 금지 표현·출력 형식의 **정본**

> 이 파일의 규칙은 **출력 형식 자체**다. 요약·생략하지 않는다.
> 목적: 가상 결과가 3주 뒤 "실제로 들은 이야기"로 기억되는 것을 막는다. 라벨 한 줄로는 못 막으므로 **문장 형태와, 살아남는 기록의 형태**를 바꾼다.
> 다른 파일은 이 목록을 복사하지 않고 여기를 가리킨다(소유권 원칙 — 같은 주제의 규칙 본문은 한 곳에만 둔다).

## 0. 본문과 메타 블록의 구분 (§4 검사 범위의 전제)

| 구역 | 범위 | 금지 표현 검사 |
|---|---|---|
| **본문** | 첫 줄 헤더 ~ `## 한계` 절 끝(논점 표·`(가상) 변경 후보` 블록·질문 표 포함) | **적용** |
| **메타 블록** | `## log.md에 붙여넣을 기록 줄`(확정 턴) · 점검 안내 1줄 · 마지막 출처 줄 | **적용하지 않음** — 검사기·기록 형식이라 금지 표현이 예시로 들어 있다. **예외: 기록 줄의 치환값은 §4 검사 대상**(아래) |

외부 점검 프롬프트(§8)에 붙이는 범위는 §8이 정한다 — 제안 턴은 본문까지, 확정까지 마쳤으면 확정 턴 출력을 이어 붙인다.

SKILL.md §7의 **감지·중단 보고는 실행 산출물이 아니며 이 계약의 본문·메타 블록이 아니다.** 따라서 중단 턴에는 고정 헤더·실행 ID·실행 메타·기록 줄·점검 프롬프트·출처 줄을 내지 않는다. 사용자 재승인 뒤 완료 산출물을 만들 때부터 이 계약 전체를 적용한다.

**경로 가드·입력 보완·타깃 확인·표본 부족·M3 형식 차이·§7 감지**로 생성을 시작하거나 완료하지 않은 응답도 같다 — 실행 산출물이 아니므로 헤더·실행 ID를 내지 않고, 완료 산출물부터 이 계약 전체를 적용한다.

후속 답변처럼 `## 한계` 절이 없는 출력은 **메타 블록을 내지 않는 한 답변 전체가 본문**이다.

**기록 줄은 고정 라벨을 제외한 치환값**(`가상가설=`·`다음행동=` 뒤 내용)**에 §4 검사를 적용한다.** 검사 제외는 점검 프롬프트와 출처 줄의 고정 문구로 한정한다.

## 1. 고정 헤더 (첫 줄 · 글자 그대로)

```
합성 페르소나 카드 N건 · 실제 고객 0명 · 독립 표본 아님 · 결정 상태=보류
```

- `N` = 이번 실행에 쓴 카드 수(3~5). **M5 단독은 `0`.**
- 두 번째 줄에 실행 메타(꺾쇠는 실제 값으로 채운다):
```
실행 ID=VCF-YYYYMMDD-NN · 모드=M? · 표본조건=<직렬화 문자열> · 선택 방식=<순환(무작위 아님)|지정> · 별칭=<P07,P12,P25> · 비신뢰 데이터=<트리거 미감지|감지 후 중단·사용자 재승인>
```
- **M5 단독**은 둘째 줄을 이렇게 고정한다(모델이 모드를 골랐으면 `모드=M5(모델 선택)`도 허용):
```
실행 ID=VCF-YYYYMMDD-NN · 모드=M5 · 표본조건=해당없음 · 선택 방식=해당없음 · 별칭=없음 · 비신뢰 데이터=<트리거 미감지|감지 후 중단·사용자 재승인>
```

- `비신뢰 데이터=트리거 미감지`는 SKILL.md §7의 판정식에 걸린 문장을 찾지 못했다는 자기보고다. 대상물이 안전하다고 검증됐다는 뜻이 아니다.
- `비신뢰 데이터=감지 후 중단·사용자 재승인`은 이전 턴에 §7 형식으로 중단했고, 그 뒤 별도 사용자 메시지로 같은 대상물의 계속 진행을 승인받은 경우에만 쓴다.
- **모드 값 표기**: 사용자가 모드를 지정하면 `모드=M1`, 모델이 의도에서 골랐으면 `모드=M1(모델 선택)`, 복수 모드면 `모드=M1+M2(모델 선택)`처럼 `+`로 잇는다. 복수 모드도 실행 ID·표본은 1벌이다.

**확정 턴 재부착**: 사용자의 질문 선택을 받아 확정 질문지를 내는 턴에는 첫 줄 헤더와 둘째 줄을 다시 붙이고 둘째 줄 맨 끝에 ` · 확정 턴(새 실행 아님)`을 덧붙인다. 확정 턴은 후속 답변이 아니다 — **기록 줄과 출처 줄을 낸다**(§5-2 뼈대).

**후속 답변 재부착 범위**: 같은 대화에서 **이전 가상 결과를 인용·요약·비교·재해석하는 답변**에는 첫 줄 헤더를 다시 붙인다. 무관한 질문에는 붙이지 않는다. 여러 실행을 함께 다루면 `N`은 합계로 적고 둘째 줄에 각 실행 ID를 **완전한 형식으로** 나열한다(`실행 ID=VCF-20260806-01, VCF-20260806-02`).

- **후속 답변은 실행 ID를 새로 만들지 않고 원 ID를 그대로 인용한다.** `(후속)`·`(후속 해석)` 같은 꼬리표를 붙이지 않는다. 후속임을 밝힐 때는 둘째 줄 맨 끝에 ` · 후속 답변(새 실행 아님)`을 덧붙인다.
- `log.md` 기록 줄의 `후속`(§6)은 로그 형식이지 실행 ID의 일부가 아니다 — 화면 출력 ID에 옮겨 적지 않는다.
- 후속 답변에는 첫 줄 헤더와 둘째 줄만 다시 붙인다. **기록 줄·점검 안내·출처 줄은 다시 내지 않는다**(새 실행이 아니다). `(가상)`·근거 태그·금지 표현 규칙은 그대로 적용한다. (확정 턴은 후속이 아니므로 위 확정 턴 규칙을 따른다.)

**실행 ID 규칙**: `VCF-<YYYYMMDD>-<NN>`. `NN`은 **그 프로젝트 `log.md`의 같은 날짜 최대 번호 + 1**(2자리, `01`부터).
- 같은 세션에서 연속으로 여러 번 실행하면 **세션 안에서 1씩 올린다**(같은 번호를 두 번 쓰지 않는다).
- **[한계]** `log.md`가 없거나 직전 기록 줄이 아직 log.md에 없으면 **다른 세션의 번호와 겹칠 수 있다.** 그때는 `01`부터 쓰고 **`번호 충돌 확인 불가`를 메타 줄에 덧붙인다.** 이 스킬은 실행 턴에 파일을 쓰지 않으므로 번호를 예약할 수단이 없다.

## 2. 1인칭 인용 금지 · 줄 단위 `(가상)` 표시

**논점·이유·마찰·검증 질문은 번호(또는 불릿) 바로 뒤에 `(가상)`을 붙인다. 한 항목이 여러 줄로 접히면 — 들여쓰기 줄·`>` 인용 줄·표 안 줄 포함 — 접힌 줄에도 각각 붙인다.** 접힌 줄에서는 **Markdown 구조 표지 뒤 첫 토큰**으로 `(가상)`을 둔다 — 들여쓰기 뒤, `>` 뒤, 표의 해당 내용 셀 첫머리. **표에서는 내용 셀(논점·전제·질문)에만 붙인다** — `판`·`#`·`안`·`근거`·질문 번호 셀은 내용 셀이 아니다.

한계 절은 원칙적으로 `(가상)` 대상이 아니다. 다만 **논점에서 파생된 서술**(논점끼리 갈린다·모순된다는 표시 등)을 한계 절에 적을 때는 그 줄만 `- (가상)`으로 시작한다. 한 줄만 잘라 `spec.md`·`handoff.md`·메모에 붙여넣어도 표시가 따라가야 한다. 블록 단위 경고는 복사 과정에서 떨어져 나간다.

| 금지 | 대체 (논점 표의 행) |
|---|---|
| `P07(34): "저는 첫 모임이 부담스러워요"` | `❌ \| (가상) 첫 참여 부담이 진입 장벽으로 작동함 \| [카드 단서: P07 가구] \| …` |
| `"가격이 비싼 것 같아요"라는 반응` | `❌ \| (가상) 가격 대비 가치가 전달되지 않음 \| [모델 생성] \| …` |

- 따옴표로 페르소나의 말을 만들지 않는다. 대사·후기·리뷰 형태의 문장을 만들지 않는다.
- 감정 묘사("망설였다", "실망했다")도 쓰지 않는다 — 카드에 없는 내면 상태다.
- 예외: 검증 질문의 `무엇으로 판정` 칸에 적는 **실제 고객의 예상 응답 예시**("주는 대로 읽는다"고 답하면 일치 등)는 페르소나의 대사·후기가 아니므로 이 금지의 대상이 아니다.

**논점 표 규칙**
- 논점 절은 표로 낸다. 열 = `판` | `(가상) 논점` | `근거` | `(가상) 전제` | `질문`.
- **`판` 열**: 번호 대신 심볼 하나 — 🟢(대상물에 우호적으로 작용할 논점) / ❌(부정·거부·마찰) / ⬛(중립·양가·갈림). 심볼도 모델 판정이므로 표의 열 제목이나 표 직전 줄에 `판(가상)`임을 밝힌다.
- **논점 셀**: `(가상)`으로 시작하는 **한 문장, 80자 이내**(M3만 120자 허용 — modes.md). 핵심을 빼면서 줄이지 않는다 — 카드와 부딪히는 상세·해설·유통 맥락은 전제 칸으로 내린다. `~라는 논점` 같은 같은 어미를 연속 반복하지 않는다.
- **전제 셀**: `(가상)`으로 시작. 이게 성립하려면 무엇이 참이어야 하는지 1문장.
- **질문 셀**: 대응하는 질문 번호(`Q1`)만.
- 복수 모드 실행이면 모드별로 표를 분리하고 절 제목에 모드를 밝힌다(`## 논점 (M1 · 반응 논점)`). 질문 번호는 모드를 가로질러 통산한다.

**변경 후보 블록** — 논점 표 아래 고정 절:
```
## (가상) 변경 후보 — 미검증
> **(가상) <제작물을 고치거나 더할 만한 후보 한 줄>** — 근거: [카드 단서: P12 목표] · 확인: Q4
- 위 후보의 채택·반영은 실제 고객 근거 확인 후에만(SKILL.md §3).
```
- 후보는 **명령형이 아니라 후보형**으로 쓴다("~를 추가한다"가 아니라 "~를 추가할 후보"). "바꾸겠습니다"·"반영합니다" 같은 결론 문장은 §3 위반이다.
- 후보마다 근거 태그와 확인 질문 번호를 붙인다. 후보가 없으면 "생성되지 않음"이라고 적는다.

## 3. 근거 태그 (논점마다 필수 · 3종)

| 태그 | 언제 | 뜻 |
|---|---|---|
| `[카드 단서: P07 <필드>]` | 카드의 실제 문장에서 나왔을 때 | **근거가 아니라 단서다.** 합성 문장이 그렇게 적혀 있었다는 것뿐 |
| `[모델 생성]` | 카드에 근거가 없을 때 | 부끄러운 표시가 아니라 **기본값**. 애매하면 이걸 쓴다 |
| `[사업 가설]` | 사용자가 이번 실행에서 **명제 형태로 직접 준 가설 문장**에서 나왔을 때 | '첫 참여 불안'·'리뷰 의존'·'가격 민감' 등 — **데이터셋 필드가 아니다.** 카드에서 나온 것처럼 섞지 않는다 |

`[카드 근거]`라는 말은 쓰지 않는다 — '근거'라는 단어가 사실 승격을 유도한다.

- **`알고 싶은 것`(주제·질문)·모드·표본 조건은 가설이 아니다.** 사용자가 가설 문장을 주지 않았으면 `[사업 가설]`을 쓰지 않는다 — 카드 문장에서 나왔으면 `[카드 단서]`, 아니면 `[모델 생성]`이다. 모델이 사용자 의도를 추정해 만든 가설도 `[모델 생성]`이다.
- 이 태그를 붙인 논점은 §5 뼈대 입력 절의 `사용자가 입력한 가설` 줄에 대응 문장이 있어야 한다 — 대응 줄이 없으면 태그가 틀린 것이다.

## 4. 금지 표현 (본문에만 적용 — §0)

> ⚠️ **동기화 규칙**: 이 목록을 고치면 §8 점검 프롬프트 6번 항목을 **같은 수정에서** 함께 고친다. 한쪽만 고치면 외부 점검이 무력화된다.

**통계·대표성**
`한국 고객은` · `20~40대는` · `대부분/대다수 고객` · `시장 반응` · `대표 표본` · `3명 중 2명` · 가상 결과에 붙인 모든 비율·백분율 · `통계적으로 유의` · `신뢰도` · `유의미한 차이`

**사실 승격**
`검증됐다` · `입증됐다` · `확인됐다` · `데이터가 말한다` · `실제 고객의 목소리` · `패널의 합의` · `고객들이 원한다`

**수요·가격 판단**
`수요가 있다/없다` · `적정 가격` · `이 가격이면 산다` · **전환율·이탈률 등 지표가 오른다/내린다는 예측(방향 무관)** · `잘 팔릴 것`

**예외 — 표본·팩의 구성 사실은 여기 해당하지 않는다.** "이 층은 5건 전원 남자", "카드 3건 중 2건이 60대"처럼 **반응이 아니라 표본 자체를 세는 서술**은 한계 절이 요구하는 정보다. 금지되는 것은 **가상 반응·의견에 붙인 비율**("3명 중 2명이 부담을 느낌")이다.

**약한 완충어**
`공통 반응` → **`모델이 반복 생성한 논점`**
`대체로` · `어느 정도` · `약간` · `다소` — 정량화 못 하면 아예 쓰지 않는다.

> 금지 표현은 **사용자가 그 단어로 물었을 때도** 본문에 쓰지 않는다. 질문을 다시 표현해 답한다.

## 5. 출력 뼈대 (제안 턴·확정 턴 2단)

### 5-1. 제안 턴 (실행 턴)


## 6. 기록 줄 (확정 턴에 화면으로 — 기록은 사용자 붙여넣기 또는 "기록해" 지시로만)

**독립된 새 엔트리를 만들지 않고, 그날 날짜 엔트리 안에** 넣는다. 사용자가 "기록해"라고 지시하면 모델이 화면에 낸 줄을 **한 글자도 바꾸지 않고** 붙인다(SKILL.md §5 7-b).

> `log.md`는 **선택 사항**이다. 없으면 스킬이 만들지 않고 "기록할 곳이 없다"고 알린다. 다만 이 파일이 없으면 §5 3-3의 표본 순환이 매번 처음으로 되돌아가 같은 카드가 반복해서 뽑힌다 — 그래서 쓰는 것을 권한다.

**(가) 그날 엔트리가 이미 있을 때** — `한 것` 또는 `검증` 절에 한 줄:
```
- 가상고객[VCF-20260806-01] 합성 카드 3건·실제 고객 0명·결정 보류 · 대상=<파일·버전> · 모드=M1 · 표본조건=30-44|수도권|전체|-|- · 후보=17명 중 3명 · 별칭=P11,P12,P13 · 팩=v1 · 가상가설=<한 줄> · 질문선택=<1a,2b,3a|전부 a> · 실제근거=미수집 · 판정=대기 · 다음행동=<한 줄>
```
- 기록 줄은 `- ` 불릿 포함 형태가 정본이다 — (가)·(나) 어느 쪽이든 같은 형태로 붙는다.
- `다음행동`에는 **검증 행동**(누구에게 무엇을 어떻게 확인할지)만 적는다 — 제작물 변경·기능 결정을 적지 않는다(SKILL.md §3).

**(나) 그날 엔트리가 없을 때** — 아래를 통째로 낸다:
```
## 2026-08-06 · <제목>

### 한 것
- 가상고객[VCF-20260806-01] … (위 (가)의 한 줄)

### 검증
- 가상 결과이며 실제 고객 근거 0건 — 판정 대기
```

- **`합성 카드 N건·실제 고객 0명·결정 보류`를 줄 안에 넣는다.** 화면 헤더는 사라지고 이 줄만 남기 때문이다.
- **UUID는 적지 않는다**(별칭은 익명화가 아니므로 프로젝트 파일에 역추적 열쇠를 남기지 않는다). 필요하면 `sampling-record.md` §5를 본다.
- **`표본조건`은 SKILL.md §5 3-1의 직렬화 문자열 그대로.** 이게 다음 실행의 순환 열쇠다.
- 실제 고객 근거가 생기면 **같은 실행 ID로 한 줄 더** 붙인다(앞 줄을 고치지 않는다):
```
가상고객[VCF-20260806-01] 후속 · 실제근거=2026-09-02 인터뷰 4명 · 판정=불일치 · 다음행동=<한 줄>
```
- `판정` 값: **최초 기록 줄은 `대기` 고정**, 실제 근거가 붙는 **후속 줄에서는 `일치` / `불일치` / `모름` 셋만**. 애매하면 `모름`. 실명·연락처는 적지 않는다.
- `가상가설=`에는 **이번 실행의 중심 (가상) 논점을 한 줄로 요약**해 적는다 — 나중에 실제 근거와 대조할 기준이므로 `없음`이라고 쓰지 않는다(사용자가 가설을 안 줬어도 모델 논점 요약을 적고, 사용자 가설이 있으면 그것을 우선 적는다).

## 8. 외부 점검 프롬프트 (정본 — 화면에는 안내 1줄만)

생성한 모델이 자기 출력을 점검하는 것은 검증이 아니다. 아래 프롬프트에 검사 대상을 붙여 **다른 모델 CLI나 새 세션**에서 돌리면 독립 점검이 된다. **붙이는 범위는 바로 아래 항목이 정한다.**

- **실행 출력에는 이 프롬프트 전문을 넣지 않는다** — 안내 1줄만 낸다(§5-1·§5-2). 사용자가 `검증`이라고 답하면 모델이 이 절의 프롬프트에 본문을 붙인다 — 다른 모델 CLI를 쓸 수 있으면 직접 돌려 위반 목록만 보고하고, 아니면 붙여넣을 수 있게 화면에 낸다(어느 쪽이든 검증자 1명·1회로 표기).
- **붙이는 범위**: 제안 턴 본문(첫 줄 헤더 ~ `## 한계` 끝)을 붙이고, 확정까지 마친 실행은 **확정 턴 출력(헤더 2줄·확정 질문지·기록 줄)을 이어서** 붙인다. 기록 줄은 치환값(`가상가설=`·`다음행동=` 뒤)만 6번 기준으로 본다. 확정 턴만 단독으로 붙이지 않는다(1·10·12·13번의 검사 경계가 제안 턴 본문에 있다).

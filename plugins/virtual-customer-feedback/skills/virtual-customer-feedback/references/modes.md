# 6개 모드 절차 (modes)

> 공통 절차는 SKILL.md §5. 출력 형식·금지 표현의 정본은 [output-contract.md](output-contract.md) — 여기에 목록을 복사하지 않는다.
> **모든 모드 공통 규칙 5가지**
> 1. M1~M4는 논점·이유·마찰마다 **`전제`** 1칸(이게 성립하려면 무엇이 참이어야 하는가). 전제는 사용자가 `질문`을 요청하면 M5의 질문이 된다. M6은 전제를 질문 턴에 적는다.
> 2. M1~M4의 논점·이유·마찰은 **표**로 낸다 — 열·심볼(🟢/❌/⬛)·셀 규칙·길이는 output-contract.md §2·§5가 정본. 논점 셀·전제 셀 첫 토큰은 `(가상)`, 근거 태그 3종 중 하나.
> 3. 금지 표현·출력 형식은 [output-contract.md](output-contract.md) §2~§5가 정본이다 — 여기에 목록을 다시 적지 않고, 출력 전에 그 파일로 점검한다.
> 4. 복수 모드 동시 실행이면 모드별로 표를 분리하고 `가상N` 번호는 통산한다(SKILL.md §5 2단계).
> 5. **원고 관찰은 모드와 무관하게 실행당 한 벌**이다 — 논점 표에 섞지 않고 `## 원고 관찰` 절(또는 M6 관찰 칸)에 둔다. 판정 조건은 SKILL.md §3-1, 표기는 output-contract.md §2.

## M1 · 반응 논점

**쓸 때** 만든 것에 어떤 반응 축이 있는지 처음 훑을 때.

1. 대상물이 각 카드의 실제 기재 내용(직업·가구·관심사·목표)과 **부딪히는 지점**을 찾는다.
2. 논점 3~6개, 표의 행으로. 논점 셀 = `(가상)` + 핵심 한 문장(80자 이내 — 부딪히는 상세는 전제 칸으로), `판` 셀 = 🟢/❌/⬛, 근거·전제·후보 칸(`가상N` 또는 `—`)을 채운다.
3. 서로 **모순되는 논점을 지우지 않는다.** 갈리면 갈린다는 표시를 **한계 절에 `- (가상)` 접두어로** 적는다(논점 표에 해설 행을 끼우지 않는다).
4. **개수를 세지 않는다**(3명 중 2명 금지). 반복되면 이렇게 쓴다:
   `- (가상) 서로 독립이지 않은 생성에서 같은 논점이 다시 나옴` — `여러 카드에서 공통` 같은 표현은 소표본 합의처럼 읽히므로 쓰지 않는다(한계 절에 적을 때도 `(가상)` 접두).

## M2 · 거부·이탈 이유

**쓸 때** "왜 안 쓰지?"를 좁힐 때. **M1과의 차이 = 부정 축만 본다.** 좋은 점은 이 모드에서 다루지 않는다.
(M1로도 부정 논점은 나오지만, M2는 **부정만 남기고 전제를 싼 순서로 정렬**해 다음에 물어볼 것을 바로 만든다.)
**글·대본·슬라이드를 읽다가 덮는 지점은 M2가 아니라 M6이다** — M2는 서비스·기능을 안 쓰는 이유를 본다.

1. 각 카드에 대해 **하지 않을 이유**만 생성한다.
2. 이유마다 전제를 붙인다.
   예: `이유=설명이 길어 끝까지 안 읽음` → `전제=이 사람이 이 화면을 스마트폰으로 처음 본다`
3. "이런 사람은 원래 안 쓴다" 같은 집단 단정 금지. **이유는 대상물에 대한 것이지 사람에 대한 것이 아니다.**
4. 이유를 다 만든 뒤 **가장 싸게 확인할 수 있는 전제 순으로** 표 행을 정렬한다(그게 먼저 물어볼 것이다). 이 모드는 부정만 보므로 `판` 열이 ❌ 일색이어도 정상이다 — 정보는 정렬 순서가 담는다.

---

## M3 · 두 안 대조

**쓸 때** A안·B안 중 어디서 갈리는지 볼 때.

1. A안·B안을 받는다. **한쪽이 훨씬 자세하면**(기준: 분량이 2배 이상 차이 나거나, 한쪽에만 표·FAQ·절 구조 같은 형식 요소가 있음) **그 턴에는 생성하지 않고 묻는다** — "형식 차이 자체가 결과를 만들 수 있습니다. 맞춰서 다시 주시겠어요, 아니면 이 차이를 감안하고 진행할까요?" **사용자의 답이 온 다음 턴에만 진행한다.** 진행을 택하면 그 차이를 한계 절에 적고, **그 재개 턴의 물리적 첫 줄도 고정 헤더다**(전환 문장 금지 — SKILL.md §5 2단계). 대상물을 함께 준 것·한쪽을 "상세판"이라 부른 것은 진행 선택이 아니다.
2. 카드마다 A·B 각각의 논점을 만들고 **갈리는 지점**만 뽑는다.
3. **"A안이 낫다/이긴다"고 쓰지 않는다**(하드 룰 — 기능 채택). 표의 행으로: `판` 셀 = ⬛(갈림), 논점 셀 = `(가상) 갈리는 지점=<무엇> · A: <한 줄> · B: <한 줄>`(**M3만 120자까지 허용**), 전제 셀에 `(가상)` + 차이를 만드는 것으로 보이는 요소와 성립 조건을 적는다.
4. 갈리지 않으면 `(가상) 이 표본에서는 갈리는 지점이 생성되지 않았다`고 그대로 적는다. **억지로 차이를 만들지 않는다.**

## M4 · 첫 경험 마찰

**쓸 때** 처음 접하는 사람이 어디서 막히는지 볼 때.

1. 대상물을 **순서(단계)로 쪼갠다.** 순서를 모르면 사용자에게 묻는다 — 임의로 만들지 않는다. (대상물이 읽는 글·대본·슬라이드이고 알고 싶은 것이 흥미·읽다 덮는 지점이면 M6을 쓴다.)
2. 단계마다 표의 행으로: 논점 셀 = `(가상) <단계>: <막힐 수 있는 지점>`, 전제 셀 = `(가상)` + 그 지점에서 없는 정보와 성립 조건. 마찰 모드이므로 `판` 열은 대개 ❌다.
3. **"이 연령대는 이런 걸 어려워한다"는 금지**(SKILL.md §8). 마찰은 **화면·문구·순서의 문제로만** 기술한다.
4. 마찰이 없다고 판단되는 단계는 "생성되지 않음"으로 남긴다.

## M5 · 검증 질문 설계

**쓸 때** 실제 고객에게 물을 것을 만들 때.
- **단독 실행 시 페르소나를 뽑지 않는다** — 사용자가 준 가설·주제를 질문으로 바꾼다. 헤더 카드 수 `0건`, 둘째 줄은 `표본조건=해당없음 · 선택 방식=해당없음 · 별칭=없음`, SKILL.md §5 3단계 생략. 태그는 **명제형 가설을 줬으면 `[사업 가설]`, 주제·질문만 줬으면 `[모델 생성]`**. 대상물은 선택 사항이다(가설·주제만 받아도 된다).
- **단독 실행 출력에는 원고 관찰·논점 표·변경 후보 절이 없다** — 질문 2안 표만 내고, 근거 태그는 질문 셀 끝에 붙인다.
- M1~M4·M6 실행 뒤에는 **사용자가 `질문`을 요청할 때만 붙는다**(그때는 논점·M6 가상 셀이 입력, 원고 관찰은 대상 아님).

**2안 제안→선택 구조**: 논점(또는 가설 축) 1개 → 질문 완성안 **2개(`a(권장)`·`b`)**. 두 안 모두 네 칸을 채우고, a와 b는 접근이 실제로 달라야 한다(예: a=행동관찰, b=설문 / a=과거 행동을 묻기, b=기존 데이터 확인). 표 형식·선택 안내·확정 턴은 output-contract.md §5가 정본.
- **M5 단독에서 가설이 여러 확인 축을 담으면 축 단위로 쪼개 질문을 만들 수 있다** — 쪼갠 축 목록을 입력 요약에 명시하고, 질문 수 = 축 수로 센다. 사용자 가설 문장에서 나온 축은 `[사업 가설]`, 모델이 덧붙인 축은 `[모델 생성]`(output-contract §3의 의미 그대로).

| 항목 | 내용 |
|---|---|
| 질문 | 실제로 그대로 읽을 수 있는 문장 |
| 누구에게 | 어떤 사람에게 물어야 답이 의미 있는가 |
| 무엇으로 판정 | 어떤 답이 오면 `일치`, 어떤 답이 오면 `불일치`인가 — **미리** 정한다 |
| 어떻게 | **`대화` `설문` `행동관찰` `기존 데이터` 4개 값 중 하나만** — 실행 ID 참조·주석·조건문을 이 칸에 넣지 않는다 |

**질문 작성 규칙**
- 행동·경험을 묻는다: `최근에 ○○을 해 본 적이 있나요? 그때 어떻게 하셨어요?`
- 의견·미래를 묻지 않는다: `이 기능 있으면 쓰시겠어요?`(× — 누구나 예라고 한다)
- 유도하지 않는다: `이거 편하시죠?`(×)
- 대상물을 설명한 뒤 묻지 말고, **먼저 현재 행동을 묻고 나중에 보여준다.**
- 한 문장에 하나만 묻는다.

**판정 기준은 반드시 미리 적는다.** 답을 듣고 기준을 만들면 무엇을 들어도 "맞았다"가 된다.

## M6 · 읽힘 진단

**쓸 때** 글·대본·캐러셀 슬라이드·상세페이지처럼 **순서대로 읽거나 넘기는 대상물**이 흥미로운지, 읽다가 어디서 덮을 수 있는지 볼 때.
(M4는 화면·절차에서 막히는 곳, M2는 서비스를 안 쓰는 이유다 — **읽는 도중의 흥미와 중단**은 M6이다.)

1. **구간을 나눈다.** 대상물 자체의 표지를 쓴다: 제목 → 소제목·장면 구분·슬라이드 번호 → 빈 줄로 나뉜 문단 순. 표지가 없어 나눌 수 없으면 사용자에게 묻는다 — 임의로 만들지 않는다.
   - 구간은 **10개 이하**. 넘으면 이웃한 구간을 합치고 그 사실을 `구간 나눔` 줄에 적는다(말없이 자르지 않는다).
2. **원고 관찰 칸을 먼저 채운다** — SKILL.md §5 2단계 끝에서 뽑아 둔 `관찰N`을 해당 구간에 번호째 적는다. 없으면 `생성되지 않음`. 카드를 읽은 뒤 새로 떠오른 지적은 관찰로 올리지 않는다.
3. **`(가상) 당기는 점` · `(가상) 닫을 수 있는 지점`**을 구간마다 선정 카드 기준으로 만든다.
   - 셀마다 `(가상)` + 한 문장(80자 이내) + 끝에 근거 태그. 해당이 없으면 `생성되지 않음` — **억지로 채우지 않는다.**
   - '닫을 수 있는 지점'은 **원고의 무엇 때문인지**(길이·순서·제목의 약속과 내용의 어긋남 등)로 쓴다. "이 연령대는 긴 글을 싫어한다" 같은 사람에 대한 단정은 금지(SKILL.md §8).
   - **지표 예측 금지** — "이탈률이 오른다"·"완독률이 낮을 것"을 쓰지 않는다. 지점만 말한다(output-contract.md §4).
   - 개수를 세지 않는다(3명 중 2명 금지). 한 셀에 한 논점.
4. **전제 칸은 두지 않는다.** 사용자가 `질문`을 요청하면 질문 턴에 질문마다 `(가상) 전제`를 적는다(SKILL.md §5 5단계).
5. 가상 셀에서 나온 수정 후보는 `## 변경 후보` 절에 `가상N`으로 적고, 셀 끝에 `→ 가상N`을 붙인다. 표 형식 정본은 output-contract.md §5-1b.
6. **구간끼리 "가장 지루한 구간"처럼 순위를 매기지 않는다.** 어느 지점을 먼저 고칠지는 사용자가 표를 보고 정한다(SKILL.md §3-2와 같은 원리).

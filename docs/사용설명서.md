# 사용설명서 — 가상 고객 피드백

처음 쓰는 분을 위한 문서입니다. **이 문서 하나만 읽으면 됩니다.** 개발 지식은 필요 없습니다.

---

## 0. 이 도구가 뭘 하는지 먼저

당신이 만든 것(랜딩 페이지·안내문·앱 화면·카드뉴스·글)을 주면, **고칠 부분 후보를 두 갈래로 나눠 줍니다.**

- **원고 관찰** — 원문만 보면 맞다/틀리다가 갈리는 사실(예: 제목의 "30분"이 본문에 한 번도 안 나옴). 가짜가 아니므로 바로 고쳐도 됩니다.
- **가상 반응** — 한국 성인 합성 페르소나 3명이 어떻게 반응할지 뽑은 논점. 이건 **확인 전의 가설**입니다.

원하면 그 가설이 맞는지 실제 고객에게 물어볼 **질문지**도 만들어 줍니다.

**중요 — 이 도구는 "고객이 뭐라고 할지"를 알려주지 않습니다.** 페르소나는 진짜 사람이 아니라 통계로 만든 가짜 데이터입니다. 그래서 가상 반응은 전부 **"확인해 봐야 할 가설"**입니다. 가상 반응에서 나온 후보로 제작물을 고치는 것은 **당신이 번호를 짚어 고를 때만** 합니다.

이 도구를 제대로 쓰는 순서는 이렇습니다.

```
① 결과를 본다  →  ② 원고 관찰은 고치고, 가상 후보는 골라서 고친다  →  ③ 중요한 가설은 질문지로 만들어 진짜 고객 3~5명에게 물어본다  →  ④ 답을 기록한다
```

③을 건너뛰고 가상 후보만 계속 반영하면 가짜 결과를 진짜로 착각하기 쉽습니다. 고른 기록이 `log.md`에 남는 이유가 그것입니다.

## 1. 설치 (한 번만)

### 가장 쉬운 방법

Claude Code 채팅창에 아래를 **그대로 붙여넣으세요.** 나머지는 Claude가 알아서 합니다.

```
https://github.com/hapum0225/virtual-customer-feedback 이 스킬을 사용할 수 있는 상태로 세팅해줘
```

설치 중에 Claude가 "출처를 확인해 달라"고 하면, 위 GitHub 주소가 맞는지 보고 진행하라고 답하면 됩니다.

### 직접 명령으로 하는 방법

```bash
claude plugin marketplace add hapum0225/virtual-customer-feedback
claude plugin install virtual-customer-feedback@virtual-customer-feedback --scope user
```

### 설치 확인

새 채팅을 열고 아래 중 하나를 입력했을 때 스킬이 반응하면 성공입니다.

```
/virtual-customer-feedback:virtual-customer-feedback
```

플러그인 스킬은 `/플러그인이름:스킬이름` 형태를 씁니다. (저장소를 직접 복사하는 수동 설치라면 짧은 `/virtual-customer-feedback` 입니다.)

**슬래시 명령을 외울 필요는 없습니다** — 그냥 채팅에 `가상 고객 피드백 돌려줘` 라고 해도 열립니다.

반응이 없으면 → `/reload-plugins` 를 입력하거나 Claude Code를 껐다 켜세요.

## 2. 첫 실행 — 이렇게만 쓰면 됩니다

검토할 파일이 있는 폴더에서 Claude Code를 열고, 채팅에 이렇게 씁니다.

```
가상 고객 피드백 돌려줘.
대상물=안내문.md v1 / 알고 싶은 것=처음 보는 사람이 신청까지 갈지
```

**꼭 필요한 건 두 개뿐입니다.**

| 항목 | 뜻 | 예 |
|---|---|---|
| **대상물** | 검토할 파일 + 버전 | `안내문.md v1`, `landing-page.html v2` |
| **알고 싶은 것** | 뭐가 궁금한지, 한 문장 | "왜 신청을 안 할까", "어디서 막힐까" |

나머지(모드·표본)는 **안 적어도 됩니다.** 알아서 고르고, 무엇을 골랐는지 결과에 적어 줍니다.

> 💡 **버전(v1)을 꼭 적으세요.** 나중에 "v1에서 나온 논점"과 "v2에서 나온 논점"을 구분해야 하기 때문입니다.

## 3. 결과 읽는 법

기본 결과는 **한 번에** 나오고, 질문지는 원할 때 따로 만듭니다.

### 첫 번째 — 관찰 · 논점 · 변경 후보

맨 윗줄에 이런 게 붙습니다. **이 줄이 "지금 보는 게 가짜"라는 표지입니다.**

```
합성 페르소나 카드 3건 · 실제 고객 0명 · 독립 표본 아님 · 결정 상태=보류
```

먼저 **원고 관찰** 표가 나옵니다. 위치와 인용이 붙은 사실이라 원문과 대조해 보면 맞는지 바로 알 수 있습니다. 그다음 **논점 표**(가상 반응)가 나옵니다.

| 기호 | 뜻 |
|---|---|
| 🟢 | 좋게 작용할 것으로 보이는 논점 |
| ❌ | 부정적으로 작용할 것으로 보이는 논점 |
| ⬛ | 사람에 따라 갈리거나 중립인 논점 |

각 줄에는 **`전제`**가 붙습니다 — "이 논점이 맞으려면 무엇이 참이어야 하는가". 질문지를 만들면 이게 질문이 됩니다.

글·대본·슬라이드처럼 순서대로 읽는 것이고 "읽다가 어디서 덮을까"가 궁금하면 논점 표 대신 **읽힘 진단(M6) 표**가 나옵니다 — 구간마다 원고 관찰 · 당기는 점 · 닫을 수 있는 지점을 보여 줍니다.

그 아래 **변경 후보**가 두 묶음으로 나옵니다.

| 묶음 | 고치는 법 |
|---|---|
| `관찰1`, `관찰2`… (원고 관찰에서 나온 후보) | `관찰1 고쳐줘` 또는 `다 고쳐줘` |
| `가상1`, `가상2`… (가상 반응에서 나온 후보) | 번호를 짚어 `가상1 채택` — 이 도구는 어느 것을 고르라고 권하지 않습니다 |

고치는 것은 **결과를 본 뒤 다음 메시지**에서만 합니다. 결과를 부르는 같은 메시지에 "바로 고쳐줘"를 섞으면 고치지 않고 번호로 다시 지시해 달라고 합니다.

### 두 번째 — 질문지 (원할 때만)

`질문`이라고 답하면 논점마다 질문 후보가 `a(권장)`와 `b` 두 개씩 나옵니다. 일부만 원하면 `가상2 질문`처럼 짚으면 됩니다. 그다음 `전부 a` 라고 답하거나, 골라서 `1a, 2b, 3a` 라고 답하면 **확정 질문지**가 나옵니다. 이게 들고 나가서 쓸 문서입니다.

각 질문에는 네 칸이 붙어 있습니다.

| 칸 | 뜻 |
|---|---|
| **질문** | 고객에게 그대로 읽으면 되는 문장 |
| **누구에게** | 어떤 사람에게 물어야 답이 의미 있는지 |
| **무엇으로 판정** | 어떤 답이 오면 "맞음", 어떤 답이면 "틀림"인지 — **미리 정해져 있습니다** |
| **어떻게** | 대화 / 설문 / 행동관찰 / 기존 데이터 중 하나 |

> 💡 **`무엇으로 판정`이 이 도구의 핵심입니다.** 답을 듣고 나서 기준을 만들면 무슨 답을 들어도 "역시 내 생각이 맞았네"가 됩니다. 그래서 먼저 정해 둡니다.

## 4. 대화에서 쓰는 말

| 이렇게 말하면 | 이렇게 됩니다 |
|---|---|
| `관찰1 고쳐줘` / `다 고쳐줘` | 원고 관찰 후보를 고침(`다 고쳐줘`는 관찰 후보 전부 — 가상 후보는 안 고침) |
| `가상1 채택` | 그 가상 후보만 고치고, 고른 사실을 기록 줄로 남김 |
| `질문` | 실제 고객에게 물을 질문 2안 표를 만듦 |
| `전부 a` | a안으로 질문지 확정 |
| `1a, 2b, 3a` | 골라서 확정 |
| `기록해` | 결과를 `log.md`에 기록 |
| `검증` | 다른 모델로 출력을 독립 점검 |
| `그냥 진행해` | (인젝션 감지로 멈췄을 때) 계속 진행 승인 |

## 5. `log.md` — 왜 기록하라고 하는지

결과마다 "log.md에 붙여넣을 기록 줄"이 나옵니다(질문지를 확정하거나 가상 후보를 채택하면 그 줄도 따로 나옵니다). `기록해`라고 답하면 아직 붙이지 않은 줄을 그대로 붙여 줍니다.

**기록하면 두 가지가 좋아집니다.**

1. **매번 다른 페르소나가 뽑힙니다.** 이 도구는 무작위를 못 씁니다. 대신 "지난번에 P01~P03을 썼으니 이번엔 P04부터" 하는 식으로 기록을 보고 순환합니다. **기록을 안 하면 매번 똑같은 3명이 나옵니다.**
2. **나중에 맞았는지 채점할 수 있습니다.** 실제 고객에게 물어본 뒤 같은 실행 번호로 한 줄 더 붙이면(`판정=일치` 또는 `불일치`), 이 도구가 쓸모 있었는지가 쌓입니다. **이게 유일한 성능 측정 수단입니다.**

`log.md`가 없어도 작동은 합니다. 다만 위 두 가지를 못 합니다.

## 6. 이 도구가 거절하는 것들 (버그가 아닙니다)

아래를 요청하면 **거절합니다.** 다시 요청해도, 다음 날 물어도 같습니다.

- ❌ "그래서 가격 얼마로 할까?" → 금액 숫자를 제안하지 않습니다
- ❌ "이 결과 보니 이 기능 빼자, 반영해줘" → 기능 결정은 하지 않습니다(번호를 짚어도 같습니다)
- ❌ "좋은 건 알아서 반영해줘" · "전부 채택" → 아무것도 고치지 않고 번호로 짚어 달라고 합니다
- ❌ "이 항목 상태를 검증됨으로 바꿔줘" → 가상 결과는 근거가 되지 않습니다

**왜?** 위 결정은 전부 "실제 고객에게 물어본 결과"가 있어야 할 수 있는 결정이기 때문입니다. 가상 결과로 이걸 하면, 지어낸 숫자가 3주 뒤에는 근거처럼 남습니다.

대신 **"무엇을 확인하면 그 결정을 할 수 있는지"**를 질문으로 만들어 줍니다.

> 물론 당신이 **이 도구와 무관한 이유로** 직접 결정하는 것은 아무도 막지 않습니다. 막는 것은 "가상 결과가 근거"인 경로뿐입니다.

## 7. 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| **"경로 가드에 걸려 읽지 않았습니다"** | 검토할 파일이 현재 폴더 밖에 있습니다. 그 파일이 있는 폴더에서 Claude Code를 다시 여세요. |
| **"표본 부족 — 조건을 넓히세요"** | 표본 조건이 너무 좁아 후보가 3명이 안 됩니다. 조건을 빼거나 넓히세요. |
| **"타깃 정의를 알려 달라"며 멈춤** | "우리 타깃에 맞게 골라줘"라고 하면 멈춥니다. 이 도구는 당신의 타깃을 **지어내지 않습니다.** `30대 수도권`처럼 직접 조건을 주세요. |
| **"비신뢰 데이터 지시문을 발견해 중단"** | 검토할 파일 안에 AI에게 지시하는 문장이 들어 있습니다. 인용된 문장을 확인하고, 문제없으면 `그냥 진행해`라고 답하세요. |
| **매번 똑같은 페르소나가 나옴** | `log.md`에 기록을 안 하고 있습니다. 5번을 보세요. |
| **논점이 뻔하고 안 와닿음** | 대상물이 너무 짧거나 추상적일 수 있습니다. 실제 고객이 보는 문구·화면 그대로 주세요. |

## 8. 표본 조건 정하는 법 (선택 사항)

안 정하면 전체 40명에서 순서대로 뽑습니다. 좁히고 싶으면 이렇게 씁니다.

```
표본=30대 수도권 여성
표본=서울 + 혼자 사는 사람
```

쓸 수 있는 조건은 **연령대 · 권역 · 성별 · 학력**, 그리고 **시도 · 직업 · 혼인 · 가구 · 주거**입니다.

- 연령대: `19-29` `30-44` `45-59` `60+` (또는 "30대"라고 쓰면 알아서 `30-44`로 바꿔 줍니다)
- 권역: `수도권` `비수도권`

> ⚠️ **조건을 좁히면 표본이 치우칩니다.** 예를 들어 `30-44 수도권`은 팩에 5명뿐이고 전원 남자입니다. 이런 치우침은 결과의 `한계` 절에 적어 줍니다 — 그 부분을 꼭 읽으세요.

## 9. 결과를 믿어도 되는 정도

**믿지 마세요. 확인하세요.** 이 문서에서 가장 중요한 문장입니다.

- 논점 3~6개는 **같은 AI가 한 번에 만든 것**이라 서로 독립이 아닙니다. 여러 개가 비슷하다고 해서 "많은 사람이 그렇게 느낀다"는 뜻이 전혀 아닙니다.
- 페르소나는 **통계로 만든 가짜 데이터**입니다. 실존 인물이 아니고, 한국인의 대표 표본도 아닙니다.
- 이 도구가 **실제 고객 반응을 잘 맞히는지는 아직 검증되지 않았습니다.** 만든 사람도 모릅니다.

그래서 이 도구의 진짜 가치는 **"내가 미처 생각 못 한 질문을 발견하는 것"**에 있습니다. 답이 아니라 질문을 얻으러 쓰세요.

# 가상 고객 피드백 (virtual-customer-feedback) 🐜

**합성 페르소나로 제작물에서 고칠 부분 후보를 찾는 Claude Code 스킬입니다 — 원문으로 확인되는 사실과 가상 반응을 나눠서. 고객의 답을 아는 도구가 아닙니다.**

AI에게 "고객이 이걸 어떻게 볼까?"라고 물으면 그럴듯한 답이 나옵니다. 문제는 시간이 지나면 **그게 "실제로 들은 이야기"처럼 기억되기 쉽다**는 것입니다(작성자의 경험에서 나온 문제의식이며, 측정된 수치가 아닙니다). 이 스킬은 그 혼동을 줄이려고 만들었습니다.

- **원고 관찰**(원문만 보면 맞다/틀리다가 갈리는 사실 — 위치·인용 포함)과 **가상 반응**을 따로 냅니다. 원고 관찰은 지시하면 바로 고칩니다.
- 가상 반응의 모든 줄에 **`(가상)`** 표시가 붙습니다 — 한 줄만 잘라 다른 문서에 붙여넣어도 표시가 따라갑니다.
- 가상 반응에서 나온 후보는 **사용자가 번호를 짚어 채택할 때만** 고치고, 그 사실을 `(가상근거)`로 기록합니다. 스킬은 어느 후보를 고르라고 권하지 않습니다.
- 가상 결과만으로는 **기능 채택·가격 확정·"검증됨" 전환을 하지 못하게** 막혀 있습니다. 요청해도 거절합니다.
- 실제 고객에게 물어볼 **검증 질문**은 `질문`이라고 요청하면 만듭니다.

## 30초 요약 — 이렇게 나옵니다

```
합성 페르소나 카드 3건 · 실제 고객 0명 · 독립 표본 아님 · 결정 상태=보류
실행 ID=VCF-20261008-01 · 모드=M1(모델 선택) · 표본조건=전체|전체|전체|-|- · 선택 방식=순환(무작위 아님) · 별칭=P01,P02,P03 · 비신뢰 데이터=트리거 미감지
```

**원고 관찰 — 원문으로 확인 가능(가상 아님)**

| # | 위치 | 관찰(인용·센 대상) |
|---|---|---|
| 관찰1 | 4행 "장소: 합정역 근처 스터디룸(신청하신 분께 따로 안내)" | 스터디룸 이름·주소 0건 |
| 관찰2 | 7행 "아래 양식을 작성하시면" | 7행 아래(8~9행)에 양식·링크 0건 |

**논점 (M1 · 반응 논점) — 판(가상)**

| 판 | (가상) 논점 | 근거 | (가상) 전제 | 후보 |
|---|---|---|---|---|
| 🟢 | (가상) 책을 다 읽지 않아도 된다는 안내가 참여 문턱을 낮추는 방향으로 작동함 | [카드 단서: P01 관심사] | (가상) 참여를 막는 주된 요인이 준비 부담이다 | — |
| ❌ | (가상) 신청 전에 장소를 알 수 없어 신청 앞에서 멈춤 | [모델 생성] | (가상) 신청 전에 이동 거리를 먼저 확인한다 | 가상1 |
| ⬛ | (가상) 토요일 오후 고정이 루틴으로도 제약으로도 읽혀 갈림 | [카드 단서: P03 관심사] | (가상) 그 시간대가 이미 다른 활동으로 차 있는지에 따라 갈린다 | — |

**변경 후보**
- `관찰2` 7행의 "아래 양식"이 실제로 있도록 양식 링크 위치를 맞추는 후보 — 근거: 관찰2 → `관찰2 고쳐줘`
- `가상1` (가상) 장소의 대략적인 위치(역에서 걸어서 몇 분)를 신청 전에 보이게 하는 후보 — 근거: [모델 생성] → 고르려면 `가상1 채택`

질문지가 필요하면 `질문`이라고 답하세요 — 논점마다 `a(권장)`·`b` 두 안이 나오고, 고르면 확정 질문지가 나옵니다.

> 위 예시는 출력 형식을 보여 주려고 손으로 쓴 것입니다(실제 실행 출력이 아닙니다).

---|---|---|---|---|
| 🟢 | (가상) 미리 읽지 않아도 된다는 안내가 진입 문턱을 낮추는 방향으로 작동함 | [카드 단서: P01 관심사] | (가상) 참여를 막는 주된 요인이 준비 부담이다 | Q1 |
| ❌ | (가상) 신청 전에 장소를 알 수 없어 폼 앞에서 멈춤 | [모델 생성] | (가상) 신청 전에 이동 거리를 먼저 확인한다 | Q2 |
| ⬛ | (가상) 토요일 오전 고정이 루틴으로도 제약으로도 읽혀 갈림 | [카드 단서: P03 관심사] | (가상) 토요일 오전이 이미 다른 활동으로 차 있는지에 따라 갈린다 | Q3 |

**실제 고객에게 물을 검증 질문 — 2안 중 선택**

| # | 안 | (가상) 질문 | 누구에게 | 무엇으로 판정 | 어떻게 |
|---|---|---|---|---|---|
| 2 | a(권장) | (가상) 최근 3개월 안에 동네 모임을 신청한 적 있나요? 장소는 언제 아셨어요? | 최근 3개월 내 소모임 신청자 | 신청 **전에** 찾아봤다 → 일치 / 나중에 알아도 됐다 → 불일치 | 대화 |
| 2 | b | (가상) 지난 모집 문의 중 장소를 묻는 문의가 몇 건이었나요? | 운영 기록 | 장소 문의가 있으면 일치 | 기존 데이터 |

`"전부 a"` 또는 `"1a, 2b"`로 답하면 확정 질문지가 나옵니다.

## 설치

Claude Code 채팅에 아래를 **그대로 붙여넣으세요.**

```
https://github.com/hapum0225/virtual-customer-feedback 이 스킬을 사용할 수 있는 상태로 세팅해줘
```

또는 직접:

```bash
claude plugin marketplace add hapum0225/virtual-customer-feedback
claude plugin install virtual-customer-feedback@virtual-customer-feedback --scope user
```

설치 후 `/reload-plugins`를 실행하거나 Claude Code를 재시작하세요. 확인은 `/virtual-customer-feedback:virtual-customer-feedback`으로 합니다(플러그인 스킬은 `플러그인:스킬` 네임스페이스를 씁니다). 슬래시 없이 `가상 고객 피드백 돌려줘`라고 해도 열립니다.

> 자세한 설치·사용법은 **[docs/사용설명서.md](./docs/사용설명서.md)** 를 보세요. 처음이면 그 문서 하나만 읽으면 됩니다.

## 쓰는 법 (제일 짧은 형태)

```
가상 고객 피드백 돌려줘.
대상물=landing.md v1 / 알고 싶은 것=처음 보는 사람이 신청까지 갈지
```

모드·표본 조건은 안 적어도 됩니다 — 의도에서 알아서 고르고, 무엇을 골랐는지 출력에 적습니다.

결과를 본 뒤에는 이렇게 이어 갑니다: `관찰1 고쳐줘` · `다 고쳐줘`(관찰 후보 전부) · `가상2 채택` · `질문` · `기록해`.

## 6개 모드

| 모드 | 언제 | 출력 |
|---|---|---|
| **M1** 반응 논점 | 어떤 반응 축이 있는지 훑을 때 | 논점 3~6개 |
| **M2** 거부·이탈 이유 | "왜 안 쓰지?"를 좁힐 때 | 부정 축만, 확인 싼 순 |
| **M3** 두 안 대조 | A/B 중 어디서 갈리는지 | 갈리는 지점만 |
| **M4** 첫 경험 마찰 | 처음 접한 사람이 막히는 곳 | 단계별 막힘 |
| **M5** 검증 질문 설계 | 물어볼 것만 만들 때 | 질문지 (페르소나 안 뽑음) |
| **M6** 읽힘 진단 | 글·대본·슬라이드가 흥미로운지, 읽다가 어디서 덮을지 | 구간별 원고 관찰 · 당기는 점 · 닫을 수 있는 지점 |

모드를 안 정해도 됩니다. 의도가 여러 개면 **여러 모드를 한 번에** 돌리고 표를 나눠 냅니다.

## 이 스킬이 하지 않는 것 (하드 룰)

| 요청해도 안 함 | 대신 |
|---|---|
| 기능 채택·폐기 결정 | 후보로 제시 · 원하면 실제 고객에게 물을 검증 질문 |
| 가격 확정·추천 (숫자 판단) | 동일 |
| 가상 반응을 근거로 제작물(코드·카피·디자인) 변경 | **변경 후보 목록** — 사용자가 번호를 짚어 `가상N 채택`이라고 할 때만 고침(유일한 예외) |
| 상태를 `검증됨`으로 전환 | `미검증(가상)` 유지 — 채택해도 유지 |

원고 관찰(`관찰N`)은 가상 반응이 아니므로 이 표의 대상이 아닙니다 — 지시하면 고칩니다.

다시 요청해도, 다음 턴에 요청해도 같습니다. 막히는 것은 도구가 아니라 **가상 결과를 근거로 삼는 것 자체**입니다.

## 안전장치 — **전부 자연어 규칙입니다. 강제 장치가 아닙니다**

> ⚠️ **먼저 알아야 할 것**: 아래 항목 중 **코드로 강제되는 것은 하나도 없습니다.** 전부 "모델이 이 문서를 읽고 그대로 따르도록" 쓴 지시입니다. 검사기도, 파서도, 샌드박스도 없습니다.
> 그래서 이 저장소가 할 수 있는 최선은 ⑴ 규칙을 애매하지 않게 쓰고 ⑵ 지켜지는지 **실제로 돌려 확인하는 시험 세트를 함께 주는 것**입니다(`references/pilot-tests.md`). **"장치가 있으니 안전하다"고 읽지 마세요.**

- **경로 가드** — 작업 폴더 밖이나 규칙 파일이 금지한 폴더는 읽기 전에 멈추도록 **지시**합니다. 경로 문자열 판정이라 **심볼릭 링크·junction이 밖을 가리키는 경우는 걸러내지 못합니다.**
- **프롬프트 인젝션 방어** — 대상물·카드·로그 안의 `시스템 지시:` 같은 문장을 데이터로만 취급하도록 **지시**합니다. 판정도 모델이 자연어 기준으로 합니다 — 우회 가능성이 남습니다.
- **쓰기 금지** — 프런트매터에 `disallowed-tools`를 두었지만 **실측 결과 플러그인 호출 경로에서는 적용되지 않았습니다**(`Write`·`Edit`·`Bash`가 그대로 있었음). 실제로 작동하는 것은 "도구가 있어도 호출하지 않는다"는 문장 규칙뿐입니다. **"파일을 고치지 못한다"고 주장하지 않습니다.**
- **표본 순환** — `log.md` 기록을 읽어 다음 카드부터 뽑도록 **지시**합니다. 이를 수행하는 파서는 없고, 모델이 로그를 읽어 판단합니다.
- **외부 점검 프롬프트** — 생성한 모델이 자기 출력을 점검하는 것은 검증이 아니므로, 다른 세션·다른 모델에 붙여넣어 돌릴 프롬프트를 `references/output-contract.md` §8에 둡니다. **이것이 이 저장소에서 가장 믿을 만한 확인 수단입니다.**

## 페르소나 팩

한국 성인 **합성 페르소나 40건**(연령 4구간 × 수도권/비수도권 8층 × 5건)이 들어 있습니다. NVIDIA의 `Nemotron-Personas-Korea`(CC BY 4.0)에서 선별·가공했습니다.

**표본 선택은 무작위가 아니라 순환(rotation)입니다.** 스크립트를 돌리지 않는 스킬이라 실행 중 난수를 만들 수 없기 때문입니다. 직전 실행 기록을 `log.md`에서 읽어 그다음 카드부터 뽑습니다 — 기록하지 않으면 매번 같은 3건이 나옵니다.

> ⚠️ **팩은 한국·만 19세 이상 성인 기준입니다.** 미성년·해외 고객에는 쓸 수 없습니다.
> ⚠️ **"개인정보 없음"은 검증된 사실이 아닙니다.** 데이터셋 카드에 그런 문장이 없습니다. 인명 치환은 정규식 기준이라 미검사 잔여 가능성이 있고, 별칭화는 익명화가 아닙니다. **쓰기 전에 [NOTICE.md](./NOTICE.md) §3을 반드시 읽으세요.**
